# Практическая работа 14. Регулярные выражения

Выполнены задания 5, 6 и 7.

## Задание 5. Дата в формате dd/mm/yyyy

Условие: проверить, является ли строка датой в формате `dd/mm/yyyy` с годом от 1900 до 9999. При этом должны учитываться количество дней в месяце и високосные годы: `29/02/2000` — корректная дата, `29/02/2001` — нет.

Решение. Одним регулярным выражением проверяются:

- номер дня и допустимое количество дней для каждого месяца: в январе, марте, мае, июле, августе, октябре и декабре — до 31; в апреле, июне, сентябре и ноябре — до 30; в феврале — до 28;
- отдельная ветка для 29 февраля, которая допускает только високосный год;
- год от 1900 до 9999.

Високосным считается год, который делится на 4, кроме годов, делящихся на 100, но не делящихся на 400. В регулярном выражении это записано так: год, оканчивающийся на 04, 08, 12, 16, 20, 24, 28, 32, 36, 40, 44, 48, 52, 56, 60, 64, 68, 72, 76, 80, 84, 88, 92 или 96, либо год, оканчивающийся на 00, но с двумя старшими цифрами, кратными 4 (1600, 2000, 2400 и т. д.). Поэтому 1900 год не считается високосным, а 2000 — считается.

Используется `Pattern` с методом `matcher(...).matches()`, который требует совпадения всей строки с шаблоном.

Файл: `Task5.java`.

Результат:

```
Корректные даты:
29/02/2000   -> true
30/04/2003   -> true
01/01/2003   -> true
31/12/9999   -> true
29/02/2004   -> true

Некорректные даты:
29/02/2001   -> false
30-04-2003   -> false
1/1/1899     -> false
31/04/2003   -> false
29/02/1900   -> false
32/01/2003   -> false
```

## Задание 6. Проверка адреса электронной почты

Условие: проверить, является ли строка корректным адресом электронной почты согласно RFC 2822. Адреса `user@example.com` и `root@localhost` должны считаться правильными, а `myhost@@@com.ru`, `@my.ru`, `Julia String` — неправильными.

Решение. Адрес делится на локальную часть и домен по символу `@`. Локальная часть может содержать латинские буквы, цифры и допустимые специальные символы; точки не могут стоять в начале, в конце или идти подряд. Домен состоит из одной или нескольких меток, разделённых точками. Каждая метка начинается и заканчивается буквой или цифрой, внутри может содержать дефис. Одиночная метка разрешена, поэтому `root@localhost` проходит проверку. Пробелы, пустая локальная часть и несколько символов `@` не допускаются.

Файл: `Task6.java`.

Результат:

```
Корректные адреса:
user@example.com           -> true
root@localhost             -> true
user.name+tag@example.co.uk -> true

Некорректные адреса:
myhost@@@com.ru            -> false
@my.ru                     -> false
Julia String               -> false
user@.com                  -> false
```

## Задание 7. Надёжность пароля

Условие: пароль считается надёжным, если он состоит из 8 и более символов, может содержать цифры, английские буквы и знак подчёркивания, при этом обязательно содержит хотя бы одну заглавную букву, одну строчную букву и одну цифру.

Решение. В начале шаблона стоят три проверки с положительным просмотром вперёд: `(?=.*[a-z])` требует хотя бы одну строчную букву, `(?=.*[A-Z])` — заглавную, `(?=.*\d)` — цифру. Основная часть `[A-Za-z0-9_]{8,}` разрешает только указанные символы и требует длину не менее восьми. Концы строки закреплены символами `^` и `$`, чтобы вся строка соответствовала шаблону.

Файл: `Task7.java`.

Результат:

```
Надёжные пароли:
F032_Password  -> true
TrySpy12       -> true
Qwerty_123     -> true

Ненадёжные пароли:
smart_pass     -> false
A007           -> false
qwerty123      -> false
QWERTY123      -> false
Qwerty!        -> false
TrySpy1        -> false
```

В примере задания пароль `TrySpy1` указан как правильный, но в нём 7 символов, а по условию требуется не менее 8. Поэтому в проверке используется `TrySpy12` из 8 символов, а `TrySpy1` выведен среди неправильных как слишком короткий.
